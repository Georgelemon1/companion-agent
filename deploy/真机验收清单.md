# 真机验收清单（Android / Termux）

> 这份清单是给**最后一步**用的：模拟环境能证到的都证了，剩下的只有真机能给。
> 每一条都写了「怎么做」+「看到什么算过」+「不过怎么办」。
> 背景与原理见 [手机移植-裁剪清单.md](../手机移植-裁剪清单.md) 与 [README-手机.md](README-手机.md)。

## 零、准备

1. **Termux 从 F-Droid 或 GitHub 装**（Play 商店那版已废弃，会出怪问题）。
2. 把 `companion-phone.tgz` 拷到手机（13.2 MB，用数据线/云盘/adb 都行）。
3. 手机至少留 1 GB 空间（`npm install` 要装 100+ 个包）。

## 一、装（3 条命令）

```bash
pkg install -y tar
termux-setup-storage          # 弹权限框，允许
mkdir -p ~/companion-agent && cd ~/companion-agent
tar -xzf ~/storage/downloads/companion-phone.tgz
bash deploy/termux-install.sh
```

**看到什么算过**：最后打印 `[4/4] 完成。`
**不过怎么办**：把报错原文发我。注意 `termux-install.sh` 在**非 Termux 环境**（比如普通 Linux）会死在 `pkg: command not found`（exit 127），那属正常；手机上不该出现。

## 二、验环境（这一步最有诊断价值，30 秒）

```bash
node -v
node -p "process.platform + ' ' + process.arch + ' ' + process.version"
node -e "require('node:sqlite')" && echo sqlite-ok
bash deploy/flock-probe-flock.mjs && echo flock-ok
```

**要看的**：
- `process.platform` 到底是 `android` 还是 `linux`（这决定走哪条 flock 分支）
- `node:sqlite` 是否可用（不可用则应用起不来）
- flock 是否可用（不可用则**靠 shim**，见下）

**预期你会看到的失败码**（**已在真 Linux 内核 + 真 Bionic 用户态实测**，不是推断）：
| Termux 里的 Node | 走哪条分支 | 失败码 |
|---|---|---|
| **Termux 自建 `nodejs`/`nodejs-lts`**（实测 `process.platform === 'android'`） | `flock.js` 在 platform 检查处就抛 | **`ERR_FLOCK_UNSUPPORTED_PLATFORM`** —— 这就是**你实际会遇到的那个** |
| 假设有报 `platform === 'linux'` 的构建 | 去加载 `bin/musl/system.node` | `ERR_DLOPEN_FAILED`（早前我按这条推断过，**已被实测推翻**：Termux 的 node 报的是 `android`，走不到这一步） |

`termux-start.sh` 两条都能兜住——它探的是"**真拿锁成功没有**"，不去猜 platform。

## 三、启动

```bash
bash deploy/termux-start.sh
```

**看到什么算过**：
1. 日志出现 `companion 前端已就绪：http://127.0.0.1:4180`
2. **注意看有没有这一行**：`会话锁已降级为单进程空实现`
   - **打印了** → 说明原生 flock 不可用、已挂 shim（预期结果）。此后**不要对同一个 `state/sessions` 起第二个实例**（跨进程写保护已让出）。
   - 没打印 → 原生 flock 可用，最好。
3. 手机浏览器打开 `http://127.0.0.1:4180`，她应该站在那儿、会眨眼

## 四、验收她真的活着（关键：会话必须落盘）

在页面里说两句话，然后**在 Termux 另开一个会话**（左滑新建）执行：

```bash
ls -l state/sessions/*/*/session.v4.jsonl.zstd
```

**看到什么算过**：文件存在，且**再聊几句后字节数会变大**（说明每回合都在追加）。

> ⚠️ **别用 `cat` 判断内容**：`.zstd` 是**多帧拼接**，Node 的解码器只解第一帧，
> 直接看会以为"只有一行 header"甚至报 corrupt —— 文件其实有内容。看**字节数增长**最可靠。

**不过怎么办**：
- 文件不存在、或目录里只有一个 `session.lock` → shim 没生效（把第三节那行日志发我）
- 文件在但不增长 → 情况更细，连 `state/companion.log` 尾部一起发我
- **她回空话 / 文件只有 header → 先查凭据，别先怀疑 flock**：实测踩过——漏注入 `state/companion.env` 时，
  回合 **733 ms 就返回 `{"text":"","streamedChars":0}`**，表现是"能连上但回空话"，与 flock 无关。
  查法：`grep -c '^DEEPSEEK_API_KEY=..*' state/companion.env` 应为 1，且启动日志里有"已注入凭据"那行。

## 五、常驻（可选，但"当 APP 用"就靠它）

1. 装 **Termux:Boot**（F-Droid），把启动脚本放进 `~/.termux/boot/`（写法见 [README-手机.md](README-手机.md) 第四节）
2. 系统设置里把 Termux 的**电池优化设为"不优化"**，否则亮屏待机也会被杀
3. 重启手机，确认她自动回来了

**看到什么算过**：重启后不用手动敲命令，浏览器打开就是活的。

## 六、当 APP 用（PWA）

在手机浏览器里打开 `http://127.0.0.1:4180` → 菜单 → **"添加到主屏幕"**。

**为什么能装**：页面是从 `127.0.0.1` 打开的，属于**安全上下文**，不需要 HTTPS 证书。
装完就有独立图标；麦克风权限也因为安全上下文而可用（桌面走局域网 http 时反而会被拒）。

## 七、把结果发我

最少给我这四样，我就能判断下一步：

| # | 要什么 | 为什么 |
|---|---|---|
| 1 | `node -p "process.platform + ' ' + process.arch"` 的输出 | 决定 flock 走哪条分支 |
| 2 | 第三节启动日志里**有没有**"会话锁已降级"那一行 | 决定 shim 是否生效 |
| 3 | `ls -l state/sessions/*/*/session.v4.jsonl.zstd` 两次输出（聊几句前后） | 唯一可靠的"会话真落盘"证据 |
| 4 | 任何报错原文 | 别转述，原文最有用 |
